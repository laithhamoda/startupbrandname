# Audit, 2026-11-07 (Phase 0, read-only)

Scope: UX/UI, accessibility, back end, operations and privacy of Startup Brand Name, measured against WCAG 2.2 AA,
ISO 9241, Core Web Vitals, OWASP ASVS L2 / Top 10, NIST SP 800-63B, GDPR principles and ISO/IEC 25010.

## How to read this

- **Verified** means I read the code, ran a command or read the Supabase advisors during this audit. The evidence
  column says which.
- **Unverified** means it needs a run I have not done (screen readers, real devices, PDF viewers, usability
  sessions). These are listed as gaps, not as findings.
- Severity: blocker (stop), high, medium, low. Effort: S (under a day), M (days), L (a week or more).
- Nothing was changed in the product. This file is the only change.

## What is already good (verified)

- Live response headers send `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy`,
  `Permissions-Policy` and HSTS (`curl -I` on `/ar`; `apps/web/next.config.ts`).
- Row level security is on in every table the Supabase advisor listed; the 11 tables with no policy are server-only
  and deny everything to clients, as intended (advisor `rls_enabled_no_policy`, all INFO).
- Payment webhook: signature checked, body read as text, events stored once by `(provider, event_id)` with an
  advisory lock (`apps/web/src/app/api/payments/webhook/route.ts`, migration `20261025120000_m7_payments.sql`).
- CI already runs lint, typecheck, unit tests, build, bundle budget, secret scan over the full history, migration
  and RLS checks, accessibility and RTL snapshots, Lighthouse (SEO and accessibility 100), and sign-in end to end.
- A sign-in and claim limiter (D-340) and a start limiter (D-351) exist; global `:focus-visible` style exists
  (`globals.css:87`); a skip link exists; the question pages show "question N of M".
- Runbooks exist: breach response, data requests, operations; and a processing register (`docs/privacy`).

## Gaps (not yet verified, need a run)

1. Screen-reader passes in Arabic (NVDA, TalkBack, VoiceOver) on the main flow.
2. Keyboard-only run, 200% zoom and 360 px width on `/start`, the questions, the report and the PDF form.
3. Touch targets of at least 24 px (prefer 44 px): no explicit minimum was found in the UI primitives.
4. Contrast in both themes beyond what Lighthouse reports.
5. Core Web Vitals on a throttled 3G profile and a low-end Android phone; the field data does not exist yet.
6. Real usability sessions: five-second test, moderated tasks, question comprehension, investor review.
7. Sign-in codes landing in the inbox (not spam) on Gmail, Outlook, Yahoo and a local provider.
